# 단계별 개별 테스트

`.env`의 `VIDEO_FORMAT`으로 영상 포맷을 지정할 수 있습니다. 값은 `자동`, `브이로그형`, `정보형`, `체험형` 중 하나입니다. `자동`은 포맷을 따로 강제하지 않습니다. 5번, 7번과 `main.py`의 새 기획에 적용되며 포맷별 지침은 `marketing/prompts/formats/`에 있습니다.

`VIDEO_FORMAT=random`이면 가게마다 자동을 포함한 4개 중 하나를 무작위로 선택합니다. 재시도에도 같은 포맷을 사용하며 선택 결과는 기획 JSON의 `랜덤_선택_포맷`에 기록합니다.

각 테스트 파일 상단의 `PLACE_ID`를 테스트할 카카오 장소 ID로 바꾸세요. 모든 단계에서 같은 ID를 설정해야 결과 파일이 이어집니다. DB 경로, 결과 저장 폴더, 최대 사진 수와 ComfyUI 주소는 해당 단계 파일 상단에서 설정합니다.

`16_ignore_place.py`는 상단의 `PLACE_ID`에 지정한 가게의 `posible`을 `no use`로 설정해 자동 처리 대상에서 제외하고, 해당 가게의 `generated_at`, `publish_at`, `channel`을 NULL로 설정합니다. `07_one_place.py`는 이 값을 무시하고 지정한 가게를 실행하며 실행 결과에 따라 값을 바꿀 수 있습니다.

프로젝트 루트 README에 안내된 의존성과 Playwright Chromium을 설치한 뒤 VS Code에서 다음 파일을 순서대로 열어 인자 없이 실행하세요.

1. `01_place.py`: DB에서 장소 조회 → `place.json`
2. `02_reviews.py`: 후기 수집 → `reviews.json`
3. `03_photos.py`: 사진 다운로드 → `photos/`
4. `04_analysis.py`: 사진 분석 → `analysis.txt`
5. `05_plan.py`: 전략, 15초 스크립트, 유튜브 정보와 프롬프트 → `plan.json`
6. `06_video.py`: ComfyUI 영상 생성 → `video_raw.mp4`, FFmpeg 자막 합성 → `video.mp4` 및 `subtitles.ass`

결과는 기본적으로 `test/results/<장소 ID>/`에 저장됩니다. 각 단계는 앞 단계의 결과 파일을 입력으로 사용하므로 앞 단계를 실행하거나 같은 형식의 파일을 직접 준비하세요. 같은 단계를 다시 실행하면 같은 이름의 파일을 덮어쓸 수 있습니다. 사진 분석은 `photos/`, 전략 수립은 `place.json`, `reviews.json`, `analysis.txt`, `photos/`, 영상 생성은 `plan.json`의 `minimax_prompt`와 `photos/`가 필요합니다.

후기 및 사진 수집은 카카오에 접속하고, 사진 분석과 기획은 `OPENAI_API_KEY`와 해당 모델 접근 권한이 필요하며 API 사용 요금이 발생할 수 있습니다. 영상 생성은 준비된 ComfyUI 서버와 워크플로에 필요한 모델 및 노드가 필요합니다. 후기나 사진이 없는 경우 해당 결과를 출력합니다. 사진이 없는 상황과 페이지 구조를 확인할 수 없는 오류는 구분됩니다. 파일을 직접 준비할 때 사진은 `photos/photo_1.jpg`처럼 `photo_`로 시작하는 JPG, PNG 또는 WebP 파일명으로 저장하세요. 사진 분석과 영상 생성은 파일명을 정렬한 순서로 사진을 사용합니다. 이전 실행의 사진이 폴더에 남아 있으면 함께 사용될 수 있으므로 원하는 입력만 남겨 두세요.

4번은 분석한 사진 순서와 파일 정보를 `analysis_photos.json`에 저장하고, 글자가 많은 사진의 참조 사용 가능 여부를 판별합니다. 5번은 사용 가능한 사진 중 최대 9장만 골라 `plan.json`의 `선택_사진`에 순서와 이유를 저장합니다. 6번은 해당 순서대로 참조 사진을 전달합니다. 과거 분석에는 사진 판별 정보가 없으므로 4번부터 다시 실행하세요. 사진을 추가·삭제·변경한 경우에도 4번부터 다시 실행하세요.

`07_one_place.py`는 파일 상단의 `PLACE_IDS` 목록에 지정한 가게들의 전체 과정을 순서대로 실행합니다. 한 가게가 실패해도 다음 가게를 처리하며, 완료 이력이나 기존 영상에 관계없이 매번 새로 생성합니다.

7번 테스트는 후기 사진을 최대 5장 수집해 사진 탭의 사진과 함께 분석합니다. 두 곳에서 다운로드한 사진이 총 2장 미만이면 `posible`에 `less than 2 photos`를 기록하고 다음 가게로 넘어갑니다.

`07_one_place.py`는 유튜브에 업로드하거나 생성 완료 이력에 기록하지 않습니다. 가게 처리 중 오류가 나면 DB의 `posible`에 실패 사유를 기록하며, 사진 기획에 성공하면 기존 실패 사유를 지웁니다. 실패 이력과 관계없이 지정한 가게를 테스트합니다. 결과는 `test/results/07_one_place/<장소 ID>/<실행 시각>/`에 장소·후기·사진·분석·기획과 각 GPT 단계의 요청 및 응답 JSON을 단계 번호를 붙여 저장합니다. 최종 영상의 파일명은 `video.mp4`입니다. 분석 요청 JSON에는 전송한 이미지 데이터가 포함되어 파일이 클 수 있습니다. 인증 헤더와 API 키는 저장하지 않습니다.

4번, 5번과 7번의 GPT 사용량은 각 결과 폴더의 `05_gpt_token_usage.json`에 저장합니다. 호출별 입력·출력·합계와 캐시·추론 내역, 누적 합계를 기록하며 재시도와 같은 가게의 재실행도 별도 호출로 누적합니다. 과거 응답은 자동으로 추가되지 않으며 응답에 사용량이 없으면 불명으로 표시합니다. 캐시·추론 내역은 입력·출력에 이미 포함된 값입니다.

`09_youtube_popular.py`는 `.env`의 `YOUTUBE_API_KEY`로 YouTube Data API에서 조회수 순으로 짧은 영상을 검색합니다. 파일 상단에서 검색어, 후보 수, 최대 영상 길이와 게시일을 변경할 수 있으며, 제목·설명·조회수·영상 주소 등을 `test/results/09_youtube_popular.json`에 저장합니다. 영상 길이로 고른 후보이므로 쇼츠 여부는 직접 확인해야 하고, 영상 대본은 수집하지 않습니다.

`11_minimax_voice_reference.py`는 사진과 참조 WAV를 MiniMax에 보내 나레이션 음색을 시험합니다. 파일 상단의 `REFERENCE_IMAGE`에 실제 사진 경로를 지정하고 `NARRATION`을 수정합니다. 참조 음성은 `.env`의 `MINIMAX_REFERENCE_VOICE`를 사용합니다. 결과 영상과 프롬프트, 워크플로는 `test/results/11_minimax_voice_reference/`에 저장됩니다. 전체 실행과 6번 테스트도 나레이션 영상에 같은 참조 WAV를 사용합니다. 발화 유형이 없는 기존 기획은 5번부터 다시 생성해야 합니다.

`12_all_formats.py`는 파일 상단의 `PLACE_ID` 가게를 공통으로 수집·분석한 뒤 포맷별로 기획합니다. 기본 설정 `MAX_FORMATS = 4`는 자동을 포함한 4개 포맷을 실행하며, 수를 바꾸면 테스트할 포맷 수를 조절할 수 있습니다. `GENERATE_VIDEO = True`에서는 영상까지 생성하며, `False`로 바꾸면 기획까지만 진행합니다. 결과는 `test/results/12_all_formats/<가게 ID>/<실행 시각>/`에 공통 자료와 포맷별 폴더로 저장하며, 각 폴더에서 중간 자료와 GPT 요청·응답, 토큰 사용량과 기획을 확인할 수 있습니다. 포맷 하나가 실패해도 다음 포맷을 진행하며 실패 이유는 해당 폴더의 `오류.txt`에 저장합니다. 업로드와 완료 가게 이력에는 영향을 주지 않습니다.

`13_make_pickle.py`는 `res/technam_client_secret.json`의 Google OAuth 데스크톱 클라이언트로 선택한 유튜브 채널을 인증해 `res/tmp.pickle`을 만듭니다. 파일을 지역 이름으로 변경한 뒤 다시 실행해 다음 채널을 인증하세요. `tmp.pickle`이 이미 있으면 덮어쓰지 않습니다. 현재 Python 환경에 `google-auth-oauthlib`가 없다면 `python -m pip install google-auth-oauthlib`로 설치하세요.

`14_upload_reviewed.py`는 `.env`의 `YOUTUBE_START_DATE`와 `YOUTUBE_END_DATE`에 지정한 기간(양쪽 날짜 포함)의 `output/YYYY-MM-DD/HHMM/<가게 ID>/`에서 검수 완료된 영상들을 지역별 채널에 실제 업로드합니다. 기존 시간 폴더 형식도 인식합니다. 공개 시각은 날짜·시간 폴더를 기준으로 하며, 공개 시간이 지났으면 즉시 공개하고 미래라면 그 시각으로 예약합니다. 제목·본문·태그는 각 `05_plan.json`을 사용합니다. 성공한 업로드만 DB에 완료로 기록하고 이미 완료된 영상은 건너뜁니다. 이전 `진행중` 이력도 재시도하므로 업로드 도중 중단된 경우 재실행 전에 유튜브에서 실제 업로드 여부를 확인해야 합니다.

`18_check_youtube_auth.py`는 지역별 `res/<지역>.pickle`의 갱신 토큰을 Google에 확인하고 유효, 재인증 필요, 확인 불가로 출력합니다. 인증 파일과 DB는 수정하지 않으며 영상을 업로드하지 않습니다.

`15_instagram_files.py`는 `.env`의 같은 날짜 범위에 있는 완성 영상을 `test/results/instagram/<실행 시각>/<지역>/`에 복사하고, 각 지역의 영상 설명과 태그를 해당 폴더의 `전체_설명.txt` 한 파일에 저장합니다. 실행할 때마다 새 폴더를 만들며 인스타그램 업로드는 하지 않습니다.

12번 테스트는 포맷별 기획의 핵심 상황과 전개를 80자 이내로 요약해 다음 기획 요청에 전달합니다. 요약이 누적되므로 요청마다 입력 토큰이 일부 늘어나지만 GPT 호출 횟수는 늘지 않습니다.
